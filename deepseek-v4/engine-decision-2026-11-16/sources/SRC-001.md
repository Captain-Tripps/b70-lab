What the source actually says/does:
- Windows is a documented SYCL target. Release builds ship as prebuilt `llama-bXXXXX-bin-win-sycl-x64.zip` archives that bundle the SYCL runtime DLLs, so a oneAPI installation is not required at runtime for the prebuilt path.
- Source builds on Windows use `examples\sycl\win-build-sycl.bat` against an installed oneAPI toolchain (2025.x/2026.x era toolkits).
- Multi-GPU: select devices with `ONEAPI_DEVICE_SELECTOR`; the documented forms are `level_zero:0;level_zero:1` (a named pair) or `level_zero:*` (all devices). The environment-variable table lists `ZES_ENABLE_SYSMAN` as "Recommended to use when --split-mode = layer" (enables querying free GPU memory via sycl::aspect::ext_intel_free_memory).
- Multi-device runs default to `--split-mode layer`; `--split-mode tensor` requires flash attention (auto-enabled), is "currently optimized for 2 GPUs", and "other device counts fall back to a generic all-reduce".
- Intel Arc notes include XMX/DPAS quantized Flash Attention availability on Xe2 and a `GGML_SYCL_BMG_VRAM_CHECK` workaround flag for Battlemage (BMG) cards.
What it does not establish:
- No documented statement that a 4-card layer split is stable on Windows specifically; all it says is the mechanism and the 2-GPU optimization note.
- Nothing about DeepSeek-V4.1-Flash tensor layouts (that is the model PR + converter territory).
