# Preserving an edited conversation branch

**Early experimental result: 8k branch revisit improved from 8.273 s to 0.190 s to first token, with 13/13 paired answers identical.** This is one controlled A/B of a specific synthetic sequence, not a whole-model throughput result or a deployable change. The live executable and configuration are unchanged.

The slot code normally removes a shorter snapshot when a newly parked state extends it. In a sequence that edits a long message, switches conversations, appends a turn, and returns to the earlier branch, the shorter reusable snapshot can disappear despite free slot capacity. The next request then reads the full prompt again. Raising the capacity to eight slots / 12 GiB alone did not eliminate the 115k reread.

An isolated build adds `STRATA_GLM_SLOT_KEEP_BRANCH=1`: for RAM slots only, retain a strictly shorter prefix snapshot instead of superseding it; exact duplicates are still removed. The flag defaults off and existing slot-count and byte limits continue to apply. [Patch](branch-preserve.patch), [8k A/B runner](branch-8k-ab.py). Both arms used the same experimental executable, four B70s, `14,25,36` split, eight slots, 12 GiB cap, 131072 context, deterministic 64-token replies, and separate fresh server processes. They ran prime → three edits → switch → return → append, then repeated the edits and switch. [Off](off-8k-requests.jsonl), [on](on-8k-requests.jsonl), with slot and memory logs alongside.

The second cycle's third edited request took **8.273 s off vs 0.190 s on**; the option-on slot log shows the 8,110-token state restored with one token left to read. Every one of the 13 corresponding outputs had the same SHA-256 hash. Six overlapping responses in the option-off build also matched a previously recorded production-runtime 8k run. Minimum available host memory during the short off/on runs was 85.67/85.58 GiB. The full sequence elapsed 51.2/43.1 s respectively. No full-logit, vision, quality, long-duration, or production test is implied.

Retaining older branches can evict other conversations sooner, and the implementation's existing byte limit is enforced after allocating the incoming snapshot; temporary memory use can exceed the cap. Slots larger than the cap can also remain as the sole entry. The option is an experiment, not a recommendation to deploy. A 115k replay and independent repetitions are the next gates, together with broader multi-conversation, truncation, image, cancellation, memory, and stability tests. The separate [driver crash](../2026-11-11-trim-crash/) remains unresolved.

The [115k A/B](branch-115k-ab.py) began with the option off; its [prime](off-115k-partial.jsonl) matched the previous 115k hash and took 102.98 s to first token. A new proxy-managed GLM request arrived immediately afterward, so the guard terminated the isolated run to free the GPUs. The option-on arm did not run; there is no 115k speedup result. The [isolated build script](build-branch.py) recompiles only the modified generated translation unit and links copied objects; adjust all `<work>` paths before reproducing.
