# Prefill sub-batch numerical diagnosis — 2026-11-10

**Finding:** for one inspected row, the first measured difference is the layer-0 recurrent mixer's final FP16-input, FP32-output matrix multiply. Its input FP16 row matched exactly; its output differed by at most `1.86e-8`. Baseline processes that row in a 256-token remainder after a 512-token batch; sub-batch 768 processes it in a 768-token batch. The multiply uses `dpct::blas::gemm` backed by oneMKL. The observed batch-shape dependence is consistent with arithmetic ordering or algorithm selection, but the traces do not identify the library algorithm, prove a bug, or establish that this one observed difference alone causes all later differences.

The source override sets every mixer/dense and shared-expert sub-batch. Here each prefill chunk is at most 768 tokens; the default shared-expert limit is 2048 and the override is 768, so both execute the shared expert as a single batch per chunk. The mixer default is 512 and the override is 768. Other paths, intermediate rows and accumulated state may also differ.

## Split-output intervention

A second isolated diagnostic used `MAYA_DIAG_KDA_OUT_512` to split only recurrent-mixer output GEMMs into at most 512 rows while leaving the 768-token mixer sub-batch otherwise intact. [Patch](split-output.patch) applies after the preceding diagnostic patch; [runner](split-run.ps1), logs and [comparison](split-compare-result.txt) are included. This is a diagnostic prototype, not a production switch. Binary SHA-256 `23f5947f37a41f5cb4cd4dbd4e8cad05ad6d0e469d816823c746590faefbad2a`.

On the fixed 32,768-token input, diagnostic default-512 logits matched the live baseline byte-for-byte. The intervention at sub-batch 768 still differed from the baseline on 3 of 64 top tokens (rows 49, 51, 55), mean KL 0.02147, versus 4 of 64 and mean KL 0.01354 for ordinary 768. It also differed from ordinary 768 at 3 top-token positions. One run per intervention is not a quality comparison, and splitting an output GEMM cannot be assumed to reproduce the baseline input states or other batch-shaped operations. The experiment shows that this intervention does not restore baseline outputs; it does not rule out multiple numerical differences.

Single CLI prefill times were 28.081 s for the diagnostic baseline and 27.005 s for the intervention; these are not an interleaved speed benchmark. Both exited 0. The live runtime and configuration remain unchanged.
