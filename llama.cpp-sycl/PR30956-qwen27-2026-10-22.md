# Qwen3.8-27B: does `-sm tensor` with PR 30956 help? (bench box, 2026-10-22)

Follow-up to the PR 30956 test (fast `ggml_sycl_comm_exchange`): Mistral-24B in tensor split read
prompts 14% faster with the PR, and the PR's author found Qwen3.8-27B tensor prompt reads equal to layer split.
This checks whether the two 2-card Qwen3.8-27B llama-swap entries should move to tensor split on
`master-797de6-b70-r67c-pr30956` (r67c with only the PR's `ggml-sycl.dll` swapped in).

**Answer: no.** Tensor split + PR reads 30k prompts at the same speed as layer split and decodes about 18% slower
(MTP drafting). Keep both entries as they are: r67c, default layer split.

## Setup

- The bench box, cards 0,1 (`ONEAPI_DEVICE_SELECTOR=level_zero:0,1`), env = the live entries' env (no `GGML_SYCL_PIPELINE`).
- Layer arms: the live args of `qwen3.8-27b` (Q8_0) and `qwen3.8-27b-q6` (UD-Q6_K_XL): 131k ctx, q4_0 KV,
  `-b 2048 -ub 1024`, mmproj, `--spec-type draft-mtp --spec-draft-n-max 4 --spec-draft-p-min 0.1`, runtime r67c.
- Tensor arms: the same args plus `-sm tensor`, runtime r67c-pr30956. Both fit in VRAM at 131k with MTP; load took 53 s vs 33 s.
- Order A/B/B/A per model: layer / tensor / tensor / layer. `squal.py` then `sbench.py --n 512 --rounds 3 --long 30000`
  (the long read is 33,348 tokens).
- Driver: `arms\pr30956\zpr-run.ps1 -Phase ppl-qwen27 | ab-qwen27` on the bench box; logs `status-ppl-qwen27.txt`,
  `status-ab-qwen27.txt`, `pr30956-qwq{8,6}-*.{sbench,squal}.txt`.

## Correctness

`llama-perplexity`, `-sm tensor`, ub 4, 8 chunks x 512:

| model | r67c | r67c-pr30956 |
|---|---|---|
| Q8_0 | 4.8336 +/- 0.24684 | 4.8336 +/- 0.24684 |
| UD-Q6_K_XL | 4.8264 +/- 0.24682 | 4.8264 +/- 0.24682 |

Results are bit-identical. squal output is coherent in all 8 arms; tensor and layer arms give the same answers.

## Reading

- Prompt read: tensor + PR roughly equals layer split, as the PR's author measured. Unlike Mistral-24B, there is no prompt gain to trade for.
- Decode: tensor split loses about 18%. Each MTP draft/verify step is a small batch, so with only 2 cards the per-layer
  all-reduce costs more than splitting the matmuls saves. Unlike Mistral (no MTP), the PR's faster exchange does not close the gap.
- These arms did not include tensor on plain r67c, so the PR's own effect in tensor mode is not measured for this model.
  That does not change the answer: even the best tensor arm is slower than layer.

## Recommendation

No config change. `qwen3.8-27b` and `qwen3.8-27b-q6` stay on `master-797de6-b70-r67c`, default layer split.

Follow-up: why tensor split loses decode, measured by batch size, in [TENSOR-SPLIT-DECODE.md](TENSOR-SPLIT-DECODE.md).
